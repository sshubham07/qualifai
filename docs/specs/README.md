# Specs (spec → plan → tasks)

Spec-driven workflow. Each feature folder holds:

| File | Answers | Owner |
|---|---|---|
| `spec.md` | **What & why** — user stories, functional requirements (FR-n), NFRs, acceptance criteria. No tech choices. | product |
| `plan.md` | **How** — modules, data, flows, risks; links ADRs | architect |
| `tasks.md` | **Steps** — ordered, test-first tasks `T-nn`; code TODOs reference them | engineer |
